# Kiểm tra Gemini 3.1 Flash-Lite bị HTTP 400

Log hiện tại xác nhận model được gửi đúng là `gemini-3.1-flash-lite`, nhưng Google từ chối yêu cầu inference probe bằng HTTP 400. Chưa đủ thông tin để kết luận model không hỗ trợ JSON, key sai, billing chưa bật hay khu vực không được hỗ trợ. Không coi đây là lỗi RPM 13/phút chỉ từ mã 400; không tăng retry hoặc bỏ readiness để vượt qua lỗi.

Lời hướng dẫn trước “chỉ đổi GEMINI_MODEL” đúng về biến cấu hình trong notebook hiện tại, nhưng thiếu điều kiện: project phải truy cập được model mới và yêu cầu API phải được chấp nhận. Hiện chưa có xác nhận model 3.1 chạy thành công trên tài khoản/Kaggle này.

Tài liệu chính thức: [Gemini troubleshooting](https://ai.google.dev/gemini-api/docs/troubleshooting), [Gemini 3.1 Flash-Lite](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-lite). Tài liệu model có structured outputs; không thể suy ra mọi schema hoặc mọi tài khoản đều chạy được chỉ từ việc tính năng được liệt kê.

## Thay đổi đã làm trong repository

- `gemini_diagnostics.py`: phân loại thông báo SDK và trường BadRequest thành nhãn cố định. Không xuất URL, key, prompt, đường dẫn field tự do, response body hay message gốc. Gợi ý là phân loại thông báo API, không phải chứng nhận đã xác định và sửa xong nguyên nhân.
- `providers.py` và `errors.py`: giữ nhãn an toàn cùng HTTP code đến readiness; lỗi 400 vẫn không retry tự động. Không thay tên model, schema, temperature, quota hoặc tiêu chuẩn xét đáp án trong đợt sửa này.
- `kaggle/check_gemini.py`: thêm `--diagnose`. Chỉ sau probe JSON lỗi 400, thử thêm tối đa một yêu cầu văn bản tổng hợp rất ngắn, không có nội dung câu hỏi hay dữ liệu nguồn. Cùng bộ giới hạn RPM, có thời hạn và tắt retry ngầm của SDK. Không tự chạy thêm phép thử khi lỗi 429.
- `kaggle/online_remote.py`: giữ nhãn chẩn đoán an toàn trong thông tin startup.
- Kiểm thử giả lập SDK, không dùng key thật hoặc gọi API thật. Log full suite: `artifacts/reports/gemini400_20261021_tests.log`.

Kết quả local: **740/740 tests PASS**, gồm 11 kiểm thử mới về phân loại lỗi, giữ riêng thông tin bí mật, không retry 400 và không coi plain probe thành công là JSON probe đạt. `git diff --check` không có lỗi whitespace. Đây không phải kết quả inference thực tế của model 3.1 trên Kaggle.

Ngay cả khi plain probe thành công, exit code của `check_gemini` vẫn là 1 nếu probe JSON chưa đạt. Phép thử này không chứng minh nguyên nhân cụ thể chỉ là schema: yêu cầu văn bản cũng bỏ system instruction, response MIME và temperature nên chỉ xác nhận nhóm cấu hình yêu cầu có khác biệt.

Trên Kaggle, không có backend chạy ở bước lỗi này. Chạy lại cell cập nhật code để fetch `origin/main`. Giữ `GEMINI_MODEL = "gemini-3.1-flash-lite"` nếu mục tiêu là kiểm tra 3.1. Sau đó có thể chạy riêng cell dưới trước khi Run All toàn bộ:

```python
import subprocess
import sys
from pathlib import Path

root = Path("/kaggle/working/legal-agentic-rag")
python = globals().get("PYTHON", sys.executable)
args = [python, "-u", "kaggle/check_gemini.py",
        "--model", "gemini-3.1-flash-lite", "--diagnose"]
if globals().get("CONFIG"):
    args += ["--config", str(CONFIG)]
result = subprocess.run(args, cwd=root, check=False, timeout=70)
print("Diagnostic exit code:", result.returncode)
```

Exit 1 ở đây là thông tin probe chưa đạt, không phải lý do chạy đi chạy lại vô hạn. Gửi các dòng JSON chẩn đoán; không gửi key, token hoặc lỗi SDK nguyên văn. Cell bình thường của notebook cũng tự hiện `error_reason` sau khi code mới được cập nhật; không bắt buộc chạy plain probe nếu nhãn đã chỉ rõ việc cần kiểm tra.

## Đọc kết quả

| `error_reason` | Việc cần kiểm tra |
| --- | --- |
| `API_KEY_REJECTED` | Secret `GEMINI_API_KEY` và hạn chế của key/project trong AI Studio. Chỉ thay key nếu xác nhận cần thiết. |
| `REGION_UNSUPPORTED` | Khả năng dùng Gemini tại khu vực của runtime Kaggle; không giả định vị trí máy local cũng là vị trí backend. |
| `BILLING_REQUIRED` | Trạng thái billing và quyền dùng model trong project. Không tự bật thanh toán. |
| `MODEL_UNAVAILABLE` | Đúng mã model, API version và quyền truy cập model của project. |
| `SCHEMA_REJECTED` | JSON schema/structured output; xem các `error_fields` đã lọc. Không bỏ validation hoặc đổi kiểu nội dung để cho qua. |
| `PARAMETER_REJECTED` | Tham số generation trong `error_fields`. Chỉ sửa tham số khi có bằng chứng cụ thể. |
| `FAILED_PRECONDITION` | API báo thiếu điều kiện tiên quyết nhưng chưa đủ căn cứ phân loại thành billing hay region. |
| `INVALID_ARGUMENT` / `UNKNOWN` | Chưa rõ; không đoán từ mã HTTP. Xem so sánh plain probe và structured probe. |

- `STRUCTURED_REQUEST_CONFIGURATION_DIFFERS`: văn bản đơn giản có phản hồi, JSON probe chưa đạt. Cần kiểm tra khác biệt cấu hình trước khi kết luận tương thích.
- `PLAIN_REQUEST_ALSO_FAILED`: yêu cầu văn bản cũng không thành công; xem HTTP code và nhãn của nó. Không mặc định mọi lỗi ở hai phép thử có cùng nguyên nhân.
- Có thể đổi lại 3.5 để tiếp tục công việc nếu nó vẫn đạt probe, nhưng phải ghi đúng model khi benchmark; không trộn kết quả 3.1 và 3.5 vào cùng lượt đo.

Đợt sửa này không chạy lại OFFLINE, không sửa dữ liệu, không tự commit/push và không khẳng định đã sửa xong lỗi HTTP 400 trên Kaggle khi chưa có kết quả chẩn đoán mới.
